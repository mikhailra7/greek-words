# Greek Words — ТЗ

Веб-приложение для изучения и повторения греческих слов в учебной группе (до 20 человек).
Mobile-first, должно нормально выглядеть на ноутбуке 14".

Статус документа: **v0.2** — ответы на вопросы внесены (2026-09-28). Пометка **[допущение]** означает,
что решение принято по умолчанию и его можно пересмотреть.

## 1. Общая архитектура

### 1.1. Стек (согласовано)

| Слой | Выбор | Почему |
|---|---|---|
| Backend | Python 3.11+ + FastAPI | Простой, типизированный, удобно работать с PDF |
| БД | SQLite (через SQLAlchemy + Alembic) | Для 20 человек больше не нужно, один файл, легко бэкапить. Миграции позволят перейти на Postgres |
| Frontend | Vite + React + TypeScript + Tailwind CSS | SPA с жестами (свайпы), быстрый UI на телефоне |

| Импорт | Claude через подписку (чат claude.ai / Claude Code) + PyMuPDF, LibreOffice для doc/docx | Разбор страниц учебника бесплатно, без API |

Словари **общие** для всей группы (их создаёт админ), а набор активных словарей — **свой у каждого**.
Личные словари пользователей сейчас не делаем, но архитектура их допускает (`dictionaries.owner_id`,
проверки прав через одну функцию `can_edit_dictionary(user, dict)`).

**Отображение слова:** полная форма = `article + " " + greek` (например, «το νερό»), транскрипция
тоже с артиклем («to neró»). Переводы показываются через запятую: «вода».

### 1.3. Озвучка

Web Speech API в браузере работает нестабильно: на части Android/Windows нет греческого голоса,
качество разное. Поэтому:

- При сохранении слова сервер генерирует mp3 и кладёт в `media/audio/<word_id>.mp3`.
- Движок **[допущение]**: `edge-tts` (бесплатные нейро-голоса Microsoft `el-GR-AthinaNeural` /
  `el-GR-NestorasNeural`). Риск: неофициальный API, может перестать работать.
  Запасные варианты — Google Cloud TTS (бесплатный лимит большой) или браузерный Web Speech как fallback.
- Движок спрятан за интерфейсом `TTSProvider`, чтобы можно было заменить.
- Админ может перегенерировать озвучку слова.

Техническая оговорка: iOS Safari не даёт проигрывать звук без жеста пользователя. Решение —
один переиспользуемый `<audio>`-элемент, «разблокируемый» нажатием «Начать»; дальше автопроигрывание
через 0.5 с работает, т.к. каждый переход тоже вызван жестом.

### 1.4. Картинки

Claude **не генерирует** картинки, поэтому нужен отдельный источник. Варианты:

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Поиск по стокам (Pixabay / Unsplash API, бесплатно) по английскому ключевому слову от Claude | Бесплатно, реальные фото | Для абстрактных слов («однако», «быть») мимо |
| B. Генерация (OpenAI gpt-image / FLUX через Replicate) | Единый стиль, любые слова | Платно (копейки за картинку), ещё один API-ключ |
| C. Эмодзи/иконка как fallback | Бесплатно, мгновенно | Не для всех слов есть |
| D. Вырезать иллюстрацию из самой страницы учебника | Та же картинка, что в учебнике | Ненадёжно, скан низкого качества |

**Решение:** основной источник — **D (картинки из самого учебника)**, т.к. почти у всех слов на
страницах есть иллюстрации. Для слов без картинки — **A (стоки)**, если и там ничего — **C (эмодзи)**.
У админа кнопки «обрезать заново» / «найти другую» / «загрузить свою». Генерацию (B) не делаем.

Как достаём картинки из учебника (порядок попыток):
1. **PDF с вложенными картинками** (не скан): PyMuPDF достаёт изображения как объекты вместе
   с координатами; примерная рамка от Claude «притягивается» к ближайшей вложенной картинке.
2. **Скан** (вся страница — одна картинка): Claude возвращает для слова примерную рамку иллюстрации
   (нормированные координаты на странице), сервер вырезает её с запасом по краям. Точность рамок
   Claude — главный технический риск, поэтому этап 4 начинается с проверки на реальных страницах.
3. В черновике админ видит миниатюру вырезанного фрагмента и может поправить рамку мышкой/пальцем
   (простой кроппер поверх страницы) или переключиться на сток/эмодзи.

Все источники спрятаны за интерфейсом `ImageProvider`.

### 1.5. Импорт слов — без платного API

Разбор страниц делает Claude, но **не через платный API**, а через подписку: чат claude.ai
(основной путь) или Claude Code (для больших загрузок). Оба пути дают JSON одного формата,
дальше сайт работает одинаково. Перед публикацией обязателен **шаг проверки черновика**: на сканах
Claude иногда ошибается в ударениях и транскрипции.

**Путь 1 — через чат claude.ai (основной, работает и с телефона):**
```
Загрузка файла на сайт (PDF / DOC / DOCX / фото с камеры)
   → сервер приводит всё к PDF, режет на страницы, показывает превью, админ отмечает нужные
   → сайт собирает PDF только из выбранных страниц (нумерация 1..N) и показывает:
       [Скачать PDF для Claude]  [Скопировать промпт]
   → админ в claude.ai прикладывает этот PDF + вставляет промпт → получает JSON
   → админ вставляет JSON в поле на сайте → валидация
   → сервер вырезает картинки по рамкам из JSON (страница + bbox)
   → черновик словаря: правка / удаление / добавление, подсветка дублей, поправка рамок картинок
   → «Опубликовать» → озвучка, стоки/эмодзи для слов без картинки → словарь виден группе
```

**Путь 2 — через Claude Code (для больших загрузок):**
```
Админ кладёт файл в папку import_inbox/ проекта и пишет в Claude Code «разбери учебник <файл>»
   → Claude Code по скиллу проекта (.claude/skills/import-textbook) читает страницы,
     пишет JSON по той же схеме, скриптом вырезает картинки и сам проверяет, что вырезалось
   → на выходе пакет импорта: import_outbox/<имя>.zip (import.json + images/ + исходный pdf)
   → админ загружает zip на сайт → тот же черновик → «Опубликовать»
```

Общие правила:
- **Один промпт и одна JSON-схема** для обоих путей: `docs/prompts/import.md` и
  `docs/prompts/import.schema.json`, с полем `schema_version`. Кнопка «Скопировать промпт» на сайте
  и скилл Claude Code берут их из одного места.
- Почему сайт сам собирает PDF для Claude: так номера страниц в ответе Claude гарантированно совпадают
  со страницами, по которым сервер вырезает картинки (важно для DOC/DOCX и фото).
- Рамка картинки в JSON — `page` (1..N) + `bbox` в долях страницы `[x0, y0, x1, y1]` (0..1).
  Если PDF не скан и в нём есть вложенные картинки, сервер дополнительно «притягивает» рамку к
  ближайшей вложенной картинке — так вырезается точнее.
- Разбирать порциями, ориентир — **до ~5–10 страниц за раз**, чтобы ответ Claude не обрезался.
- Вставленный JSON прощается к мелочам: снимаем обёртку ```json, лишний текст до/после;
  ошибки валидации показываем по-человечески («слово 12: нет перевода»).
- **Ручное добавление/редактирование** слова — обязательно, т.к. импорт никогда не будет идеальным.
- **Импорт из текстового списка** («λέξη — слово» построчно) — тот же путь 1, просто без PDF.
- Страницы учебника **смешанные** (списки слов, диалоги, упражнения, картинки с подписями). Промпт
  должен извлекать лексику со всей страницы, приводить к словарной форме (сущ. — им. падеж ед. ч.
  с артиклем, глагол — 1 л. ед. ч.), дедуплицировать и указывать страницу и рамку картинки.
  Что именно извлекать (слова из упражнений, фразы целиком, имена собственные) уточняется
  после проверки на реальных страницах.
- **Задел на будущее:** импорт спрятан за интерфейсом `ImportProvider` (`paste`, `package`).
  Если позже появится ключ Claude API или бесплатный Gemini, добавляется провайдер `api`
  с тем же промптом и схемой — без переделки черновика. Сейчас не делаем.

## 2. Функциональные требования

### 2.1. Регистрация и вход
- Форма регистрации: имя пользователя + пароль + повтор пароля + **код приглашения**.
- Коды приглашения создаёт админ в админке: код, лимит использований (например, один общий код
  на группу на 20 использований или одноразовые коды), срок действия, возможность отключить.
  Первого пользователя (админа) можно зарегистрировать без кода, пока в системе нет ни одного юзера.
- Форма входа: имя + пароль. Сессия в httpOnly cookie, живёт 30 дней **[допущение]**.
- Лимит пользователей — 20 (настройка `MAX_USERS` в `.env`). При достижении — понятное сообщение.
- Первый зарегистрированный пользователь автоматически становится админом;
  также есть CLI-команда `python -m app.cli make-admin <username>`.
- Админ-панель: список пользователей, переключатель «админ» (любой админ может выдать или снять
  права у другого пользователя), сброс пароля, удаление; управление кодами приглашения.
  Нельзя снять права с последнего админа.
- Пароли — argon2/bcrypt, ограничение попыток входа (защита от перебора).

### 2.2. Словари
- Список словарей: название, количество слов, чекбокс «активный».
- Состояние чекбоксов сохраняется на сервере для пользователя.
- Сверху — счётчик «Активно N слов в M словарях».
- Просмотр словаря: список слов (картинка-миниатюра, греческий, транскрипция, перевод, кнопка 🔊).
- Админ: создать/переименовать/удалить словарь, добавить/изменить/удалить слово, импорт.
- Слово: греческое написание (для существительных — с артиклем), транскрипция латиницей,
  1–5 переводов на русский (до 2026-10-04 — 1–3), озвучка (произносится вместе с артиклем), картинка
  (+ опционально часть речи, пример).

### 2.3. Общие правила тренажёров
- Слова берутся только из активных словарей. Если активных нет — экран с кнопкой «Выбрать словари».
- Ползунок количества: min 1, max = число слов в активных словарях, по умолчанию
  min(20, max) **[допущение]**. Рядом показывается выбранное число.
- Последние настройки каждого тренажёра запоминаются **[допущение]**.
- Порядок — случайный, без повторов внутри сессии, при перезапуске новое перемешивание.
- Во время сессии — прогресс «5 / 20» и крестик выхода (с подтверждением, если сессия не закончена).

### 2.4. «Изучение слов»
- Настройки: чекбокс «Озвучивать слова» (раньше «Озвучивать карточку»), ползунок количества, кнопка «Начать» по центру.
- Карточка: картинка → греческое слово → транскрипция → перевод.
- Через 0.5 с после открытия карточки слово произносится (если включено).
- На карточке в правом верхнем углу — кнопка повторного произнесения.
  **Предложение:** иконка динамика 🔊, а не микрофона (микрофон обычно означает запись).
- Крестик выхода — в правом верхнем углу **экрана** (над карточкой), чтобы не конфликтовать
  с кнопкой звука на карточке.
- Переход: свайп карточки **в любую сторону = следующая карточка**, или стрелка в правом нижнем углу.
  Карточка улетает в сторону свайпа. На ноутбуке также клавиши → / ←, пробел — повтор звука.
- В конце — экран «Готово: N слов» с кнопками «Ещё раз» и «В меню».

### 2.5. «Переведи слово»
- Настройки: ползунок количества; направление RU→GR / GR→RU; чекбокс «Показывать правильный ответ сразу»; «Начать».
- RU→GR: карточка с картинкой и русским словом, 4 варианта на греческом.
- GR→RU: карточка **только с греческим словом, без картинки** (картинка подсказала бы ответ).
  В углу карточки — кнопка 🔊, звук только по нажатию, автоматически не проигрывается.
  4 варианта на русском.
- Вариант на русском = все переводы слова через запятую («дом, жилище»). В RU→GR на карточке
  тоже все переводы.
- Неправильные варианты — случайные слова из активных словарей, по возможности той же части речи.
  Дистрактор не может иметь ни одного общего перевода с правильным словом. Если в активных
  словарях меньше 4 слов — показываем столько, сколько есть.
- Нажатие на вариант = ответ.
  - Галка «показывать сразу» включена: подсветка зелёным правильного / красным выбранного
    неправильного, переход дальше **по кнопке «Далее»**.
  - Выключена: сразу следующая карточка.
- Финал: «Правильно X из N» + список ошибок (слово → правильный ответ → ваш ответ).

### 2.6. «Напиши»
- Настройки: ползунок количества, «Начать».
- Карточка: картинка + русское слово, поле ввода, кнопка ✓ справа от поля (Enter тоже отправляет).
- После отправки показываются оба варианта: «Ваш ответ» и «Правильно», с подсветкой отличий
  по буквам, затем кнопка «Далее».
- Для существительных **артикль вводится обязательно**: правильный ответ — «το νερό», ответ «νερό» — ошибка.
  На карточке нет подсказки про артикль.
- Правила сравнения:
  - не учитываются: регистр, пробелы по краям, повторные пробелы внутри;
  - **ударение (τόνος) учитывается**: «νερο» вместо «νερό» — ошибка;
  - **ς и σ различаются**: σ в конце слова вместо ς (или ς в середине) — ошибка;
  - латинские буквы, похожие на греческие (o/ο, a/α и т.п.), — ошибка, но в подсказке к ошибке
    пишем «похоже, введены латинские буквы».
- Финал: «Правильно X из N» + список ошибок.
- На телефоне экранной клавиатуры нет: греческая установлена в телефоне. На ноутбуке (от 768 px)
  под полем — экранная греческая клавиатура (добавлено 2026-09-29, см. этап 7). Полю ввода
  ставим `lang="el"`, `autocapitalize="off"`, `autocorrect="off"`, `spellcheck="false"`.

### 2.7. Интерфейс
- Mobile-first, ориентир 360–430 px ширины; на 14" ноутбуке контент по центру, макс. ширина ~480 px
  для тренажёров, словари — шире.
- Нижнее меню (tab bar) на телефоне: Словари · Изучение · Переведи · Напиши · Профиль.
  На ноутбуке — то же или боковое меню.
- Язык интерфейса — русский. Светлая/тёмная тема по системной настройке.
- Карточка целиком помещается на экран без прокрутки (учесть экранную клавиатуру в «Напиши»).
- PWA: можно «установить» на главный экран телефона (этап 8).

### 2.8. Нефункциональные
- Секреты (ключи стоков) — только в `.env`, не в git. Секрет сессий не нужен: сессия — случайный
  токен, в базе хранится его хэш (настройка `SESSION_SECRET` убрана 2026-09-30).
- Бэкап: копия SQLite + папки media (скрипт; на сервере — cron). Сделано: `deploy/backup.sh`, см. этап 9.
- Сырой JSON каждого импорта сохраняется для отладки промпта.

## 3. Этапы разработки

Каждый этап заканчивается рабочим состоянием, которое можно запустить и проверить.
Этапы 5–7 не зависят от этапа 4 и могут делаться параллельно с ним (на ручных/тестовых словах).

### Этап 0. Каркас проекта
- [x] `.gitignore`, `README.md` с командами запуска. (git — только по команде, на этапе 9)
- [x] Backend: FastAPI, конфиг из `.env`, SQLAlchemy + Alembic, healthcheck `/api/health`.

### Диалоги (ТЗ v2, согласовано 2026-10-01)

Исходное ТЗ принесли 2026-10-01; ниже — оно с правками под устройство приложения (помечены
«Правка:»), согласованными с заказчиком.

**Д1. Данные.** Диалог: название (рус.), роли (2–3 имени, напр. «Μαρία», «Νίκος»), реплики по
порядку. Реплика: роль, греческий текст (ударения, пунктуация), транскрипция, перевод, заметка.
- Правка: диалоги **общие для группы**, как словари: видят все, загружают / заменяют / удаляют
  только админы.
- Правка: у реплики обязательны `greek` и `translation_ru`; `transcription` и `note` —
  необязательные (пусто — не показываются). Ограничения: роли — 2–3, имя до 40 символов;
  реплик 2–80; реплика до 300 символов.
- Правка: поле `category` из исходного ТЗ пока не делаем — в примере JSON его нет, а «категории»
  в приложении — смысловые категории **слов**. Вернём как свободную «тему», если понадобится.

**Д2. Импорт.** JSON — как в исходном ТЗ (`schema_version: 1`, `type: "dialogue"`, `title`,
`speakers`, `lines[{speaker (индекс роли с 0), greek, transcription, translation_ru, note}]`).
- Ошибки по-человечески, как у словарей: «реплика 3, поле translation_ru: …», «реплика 5: роли
  с номером 2 нет»; обёртка ```json и текст вокруг прощаются (общий разборщик).
- Правка: **один и тот же файл** можно загрузить и в «Словарях», и в «Диалогах»: тип — по полю
  `type` (`"dialogue"` — диалог; нет поля — словарь, как раньше). Плюс «Вставить ответ Claude»
  в «Диалогах» и промпт `docs/prompts/dialogue.md` (правила транскрипции — как у слов).
- Правка: «повторный импорт» = **«Заменить из JSON»** в меню диалога (содержимое заменяется,
  прогресс диалога сбрасывается) и **«Скачать JSON»** — для правки и бэкапа. Редактора реплик
  на сайте нет: правка — через JSON.

**Д3. Раздел «Диалоги».** Пункт меню и плитка на главной. Карточка: название, роли, число
реплик, «Учить». Админ: загрузить, заменить, скачать, удалить (с подтверждением).

**Д4. Режимы** (переключатель вверху экрана диалога; выбранный режим запоминается).
- **Д4.1 Чтение / слушание.** Чат: реплики первой роли слева, остальных справа, имя роли над
  пузырём. Переключатели «Греческий / Транскрипция / Перевод» (запоминаются; хотя бы один
  включён). Тап по реплике — озвучить. «Прослушать весь диалог» — по очереди с паузой ~0,8 с,
  звучащая реплика подсвечена и прокручивается в видимую область; пауза / продолжить / стоп.
- **Д4.2 По ролям.** Выбор роли перед началом. Реплики собеседника появляются и звучат сами;
  реплика пользователя скрыта, виден перевод и кнопка «Показать». Правка: после «Показать»
  реплика **звучит** (сверить произношение), затем «Знал» / «Не знал» — только для итога прохода
  (не сохраняются, см. Д6). Итог: «Знал X из N», «Ещё раз», «Сменить роль». Распознавания речи нет — «произнести» означает вслух для себя.
- **Д4.3 Постепенное скрытие** (по отдельному запросу). Уровни 0–3: всё / ~30% слов / ~60% /
  только перевод. Правка: скрытие **накопительное и неслучайное** — на уровне 2 скрыты слова
  уровня 1 и ещё столько же (иначе на каждом уровне «новый» текст); знаки препинания не скрываются.
  «Безошибочный проход» = не открыто ни одного скрытого слова → предлагаем следующий уровень.
- **Д4.4 Сборка фразы** (по отдельному запросу). Чипы — слова без знаков препинания, регистр как
  в оригинале; одинаковые слова взаимозаменяемы; тап по выложенному чипу возвращает его.
  Проверка автоматически, когда выложены все чипы; неверно стоящие чипы подсвечиваются.
- **Д4.5 Ввод по памяти** (по отдельному запросу). Нестрогое сравнение: регистр, пунктуация,
  ударения и правка: **ς/σ** не важны. Подсказка про латинские буквы — как в «Напиши». Показ
  правильного варианта с ударениями, различающиеся слова подсвечены. Осознанно мягче «Напиши»,
  где ударение — ошибка: здесь учим текст, а не орфографию.

**Д5. Озвучка.** Реплики целиком озвучивает сервер (edge-tts), файлы кэшируются, как у слов;
голос устройства — как везде (по умолчанию). Скорость — из профиля. Правка: голосом сайта роли
звучат **разными голосами**: первая — женский, вторая — мужской, третья — женский (у Microsoft для
греческого только два голоса); галочка **«Один голос для всех ролей»** на экране диалога
(запоминается) — тогда все роли голосом из профиля. Голос устройства — один на все роли (на

**Д6. Прогресс — пока не делаем** (решение 2026-10-01). Исходное ТЗ противоречило себе: блок
«Прогресс» — «пока не делаем», а в списке «% выученных», в критериях — «сохраняется после
перезагрузки». Поэтому в первой версии нет ни % в списке, ни сохранения «Знал / Не знал», ни
сброса прогресса. Запоминаются только настройки (режим, что показывать, «Один голос»).
Интервальное повторение (1 → 3 → 7 → 14 дней, «новая / учу / выучена») — отдельным этапом.
